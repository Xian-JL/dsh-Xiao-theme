# 魈主题第二版优化方向

本文记录 `dsh-xiao-theme` 第二阶段的产品、兼容性、视觉验收和素材治理方向。当前基线为 `1.2.0`，历史验证记录见 `docs/VALIDATION.md`，接口边界见 `docs/COMPATIBILITY.md`。文档中的未完成项不会被描述为已验收。

## 1. 当前基线与已知边界

- 当前源码和包版本为 `1.2.0`，发布到公开 GitHub Release `v1.2.0`；历史市场 PR #6404 仍引用稳定的 `releases/latest` 下载链接。
- 现有实现包括双主题色板、欢迎页/会话页立绘转场、可拖动的魈伙伴、会话状态、可选余额、设置界面和动效生命周期。
- 项目现有验证记录称构建、契约及自动化用例通过，并在隔离 `xiao-lab` Profile 完成安装、组合、路由和卸载验证。该记录不是本轮重新运行所得。
- 2026-10-03 用户报告已完成 DSH 桌面端切窗复测、第三方素材许可核查、布局/缩放检查和性能采样。具体切换次数、缩放组合、性能数据及逐项素材许可结论尚未写入验证记录；本文件只记录“用户报告完成”，不据此补造测量值或授权结论。
- 用户验收截图曾确认设置预览中伙伴头像与主立绘重叠；V1.1 已移除预览叠图，同时保留主立绘实时预览。
- 插件市场 PR [#6404](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/pull/6404) 已更新；2026-10-03 新一轮常规检查与 Submission gate 均通过，仍等待维护者审核。PR 合并和市场收录尚未完成。
- 当前素材包含第三方原图。来源记录不等于再分发、去水印、改作或公开发布许可；作者与许可未核实的素材不能被描述为已获授权。

## 2. V1.1 用户验收改进

- 设置实时预览移除与主立绘重叠的魈伙伴头像；窄窗口仍保留立绘缩略图。
- 新增持久化 `characterVariant`，可在静立立绘与生日贺图间切换，两张图共用同一主立绘舞台；旧 Profile 自动回退到静立立绘。
- 傩面提高对比度、饱和度、锐化和界面不透明度。
- 呼吸、伙伴反馈、点击风痕、粒子运动和沉浸视差采用首版三倍幅度。粒子数量仍有上限，`prefers-reduced-motion` 仍会停用装饰动效。
- 魈伙伴状态/余额面板依据实际安全空间调整方向；窗口失焦、页面隐藏和卸载会清理全部点击风痕节点。
- 生日贺图主立绘用 32 px 圆角裁切，预览用 20 px 圆角；完整方图仍用于设置横幅。
- 窗口重新获得焦点时再清空一次点击风痕池，覆盖 Electron Desktop 切换外部窗口后没有发出普通页面隐藏事件的情形。
- V1.1.3 修复作者样式覆盖 `hidden` 的真实根因，并把动画子图形设为默认透明，清理后不会再显露静态边框。

## 2.1 V1.2 本地背景与独立设置页

- 允许用户选择本地背景图，客户端压缩为受长度限制的 WebP 并保存在当前 DSH Profile。
- 提供 0–100% 背景可见度滑条（默认 75%），通过浅色/深色主题表面透明度展示背景；可选从图像抽取魈主题强调色。
- 将全部魈设置从 General 行迁移到独立的 `Settings → Xiao` 分区。
- 背景、调色和独立 Settings 分区均在 1.2.0 桌面包中验证；不添加新角色素材，既有动画与 reduced-motion 行为保持不变。

## 3. 本轮发现并修复的设置反馈问题

### 3.1 “重试”按钮没有重试

原实现的写入失败按钮只清除了错误提示，没有再次提交失败的设置。现已改为保留失败时的设置补丁，点击“重试”会重新执行对应写入；部分写入后的旧版回退失败情形也会重试原始目标补丁。

### 3.2 全部复位失败仍显示成功

原实现无论写入是否成功都会提示“已恢复默认设置”。现已让写入操作返回成功状态，仅在成功时显示复位成功提示；从失败提示执行复位重试时同样遵循此规则。

### 3.3 临时提示定时器缺少卸载清理

保存结果提示的定时器此前未保存在引用中，设置面板卸载后仍可能执行状态更新。现已保存并在组件卸载时清理复位及结果提示定时器。

上述修复针对设置回馈和组件生命周期，不改变 DSH 持久设置的结构。

## 4. V2 优化优先级

| 优先级 | 方向 | 具体工作 | 通过条件 |
| --- | --- | --- | --- |
| P0 | 归档已完成的实机验收记录 | 把用户完成的切窗、布局/缩放与性能采样结果补入 `docs/VALIDATION.md`，包括实际版本、场景和观察结果 | 有可复核的记录；性能结论来自实际数据，不由动画源码推断 |
| P0 | 归档逐项素材许可结论 | 根据已完成的许可核查，逐项更新 `THIRD_PARTY_ASSETS.md` 中作者、授权范围、修改与再分发状态 | 每项公开资产的结论和依据清楚；许可未知或不覆盖当前用途的素材不被描述为可再分发 |
| P1 | 处理实机检查中发现的问题 | 对照已完成的欢迎页、会话页、设置页及缩放检查结果，按实际发现修复 | 修复有明确复现步骤和回归验证；没有问题时不做无依据的视觉改动 |
| P1 | 降低 DSH 结构耦合 | 集中管理 `[data-phase='hero']`、`[class$='_headline']` 与 ` [class$='_composerHero']` 等定位；针对目标版本验证命中和失效回退 | 目标版本有命中记录；目标节点缺失时主题回退，不操作错误元素 |
| P1 | 核实主题共存边界 | 分别验证同时安装和同时启用 Kinich/Xiao；给主题令牌与品牌插槽冲突提供清楚提示 | 不声称命名空间隔离即可避免主题服务覆盖冲突 |
| P1 | 归档并评估性能采样 | 整理已完成的同设备对比结果；若结果显示卡顿，再按数据调整动效密度或调度 | 记录设备、刷新率、场景、采样时长和结果；不凭动画源码宣称 FPS 提升 |
| P2 | 扩展运行状态适配 | 按 DSH 版本记录完成、取消、等待用户和错误字段；没有可靠信号时继续使用中性“已结束” | 不把停止、断线或未知终态展示为成功 |
| P2 | 增强安装与兼容说明 | 将声明支持版本与实际实测版本分开维护；需要时缩小未经验证的兼容范围 | README、manifest 和兼容文档表述一致 |

## 5. 实机检查清单

### 欢迎页

- 确认主标题、辅助文案、DSH 工作区选择与输入区没有重叠。
- 检查白底提取后的浅色衣物、风痕和轮廓边缘是否残留白边或被误删。
- 检查人物脸部、傩面装饰和魈伙伴之间的视觉层级。
- 反复进入与离开欢迎页，观察转场能否反向、终止并稳定落在正确页面状态。

### 会话页

- 检查长回复、代码、表格、图片预览、复制按钮、滚动条和原生菜单。
- 检查魈伙伴在侧栏变化、窗口缩放与输入区增高后是否仍可见和可拖动。
- 检查真实发送、运行、结束、停止、失败和等待状态是否与当前主视图会话对应。
- 检查隐藏页面、关闭插件、减少动态效果时的清理和状态恢复。

### 设置与无障碍

- 明暗模式分别检查正文、次级文字、状态色、分隔线、焦点环和错误提示。
- 逐项执行设置保存失败、重试、位置复位及全部复位。
- 用键盘完成开关、选项、浮标移动、面板打开关闭和焦点恢复。
- 检查屏幕阅读器能否获得明确的浮标名称、当前会话状态与余额状态。
- 在 100%、125%、150%、200% 缩放下检查内容滚动与控件触达。

## 6. 兼容性与视觉适配方案

当前实现使用 DSH 的公开主题覆盖与插槽，也依赖欢迎页阶段标记和 CSS Module 类名后缀来调整原生元素。V2 应按以下顺序处理：

1. 先验证目标 Desktop 内实际安装的 DSH 版本及其公开插槽与主题接口。
2. 将易变的 DOM 选择器集中放入一个适配模块，不让布局、主题和交互模块各自复制选择器。
3. 对可用的稳定插槽优先使用公开接口；仅将必要的原生视觉调整留给受限范围的 DOM 观察。
4. 当目标节点缺失或页面结构变化时，保持基础主题、伙伴和设置可用，并停用受影响的装饰定位。
5. 把兼容范围分成“已实测”与“声明但未实测”，按证据更新 `package.json` 与兼容文档。

性能复核时特别观察页面阶段观察器：它监听 `document.body` 子树上的节点变化，且同步时重新查询页面标记。需要通过真实长回复与导航场景确认这项观察的频率和代价，再考虑缩小观察范围或进一步过滤无关变化。

## 7. 性能与动效规则

| 项目 | V2 规则 |
| --- | --- |
| 角色呼吸、伙伴待机和环境粒子 | 作为已交付的用户可选效果继续保留；性能优化调整调度、图层、数量或启停时机 |
| 页面隐藏与插件卸载 | 停止非必要动画、视差、定时器、观察器与订阅 |
| 减少动态效果 | 清除装饰循环并保留文字、颜色、焦点与静态会话状态表达 |
| 拖动 | 每动画帧至多一次视觉位置更新，释放后再持久化位置 |
| 点击风痕 | 固定数量池，限制触发对象和绘制范围，不能截获 DSH 点击 |
| 性能结论 | 以相同设备与场景的浏览器性能记录为准；不得从 CSS 推断帧率 |

## 8. 素材与发布治理

- `assets/source/` 保留用户提供的原始文件，处理产物另行存放。
- `THIRD_PARTY_ASSETS.md` 为每项资产记录来源网址、原作者（未知时明确标未知）、用途、裁切、抠图、补绘、压缩与最终路径。
- `Xiao_bird.jpg` 的米游社文章由用户提供；文章作者与可再分发、去水印、改作条件需要核实，不从画面水印推定作者。
- `scripts/extract-assets.py` 目前会清除伙伴原图右下区域的水印条带。V2 应在获取作者/许可依据前暂停对该图执行去水印处理，并重新比较保留水印、合理裁切或不打包原图的可行性。
- `package.json` 的 `files` 白名单目前不包含原始 `assets/source/`，保持安装包不带原图；Git 仓库中的原图是否可公开仍单独取决于权利与许可。
- 代码许可不能覆盖角色图像、游戏美术、商标或社区作者素材。

## 9. 建议的版本与验收路径

### V2a：桌面验收结果归档与素材治理

- 用户报告桌面切窗、布局/缩放、性能采样和素材许可核查已完成；将测试场景、观察结果、测量数据及逐项素材结论归档到验证文档。
- 根据实际验收发现处理问题；未发现问题时保持现状。
- 跟进插件市场 PR #6404 的重新检查和维护者审核。
- 设置重试和复位反馈修复已交付，保留回归检查即可。

### V2b：体验与性能

- 仅根据实机结果调整响应式布局、原生节点适配及主题共存提示。
- 采集长回复、拖动、视差和三倍动效场景的实际性能记录，再决定是否改动画调度。
- 依据目标 DSH 版本验证会话状态字段。

### V2c：发布准备

- 重新执行项目定义的构建与自动化验证。
- 检查安装包清单、源码标识、第三方素材、许可说明和兼容声明。
- GitHub 仓库内容与可公开分发的安装包分别审核；不得因推送源码而默认允许 npm 发布。

每个阶段结束时更新验证文档，记录命令、目标 DSH 版本、实际结果和未完成项目。未经实际观察或测量的项目保持“未验证”。
